# LibroYa API: contrato

> Rutas, respuestas, errores y formato de montos. Es lo que consume el frontend; la implementación está en [backend/05-piezas-clave.md](backend/05-piezas-clave.md).

## 8. Endpoints

| Método | Ruta | Respuesta | Errores (`errorCode`) |
|---|---|---|---|
| `POST` | `/orders` (header `Idempotency-Key`; **comprador**) | `201 { orderId, charged: { amount: "90.00", currency: "PEN" } }`, también al reintentar una compra completada. El cliente es el del token: el cuerpo no lleva `customerId` | `400` DTO, falta la clave o viene un `customerId` · `401` · `403` (solo compradores) · `404 NOT_FOUND` (un libro, o el cliente aún no existe en Ventas: reintente) · `409 CHECKOUT_IN_PROGRESS` · `422 OUT_OF_STOCK`, `STOCK_ITEM_NOT_FOUND`, `PAYMENT_DECLINED`, `IDEMPOTENCY_KEY_REUSED`, `PREVIOUS_ATTEMPT_FAILED` o una regla del dominio |
| `GET` | `/orders/:id` (sesión; su dueño o un administrador) | `200 { id, status, charged: { amount, currency }, lines[{ isbn, title, unitPrice: { amount, currency }, quantity }], shippingAddress }` (líneas ordenadas por ISBN). `shippingAddress` es `{ recipient, phone, line1, district, province, department, reference }` (`reference` puede ser `null`), o `null` en un pedido anterior a que existiera la dirección. Solo la ve su dueño o un administrador (para otro es `404`); el endpoint no tiene datos personales para nadie más | `400` (el id no es un UUID) · `401` · `404 NOT_FOUND` (no existe **o es de otro comprador**: el mismo error, para no revelar que existe) |
| `GET` | `/books?q=&page=&pageSize=` | `200 { items[{ isbn, title, author, price: { amount, currency } }], page, pageSize, total }`: solo libros activos, ordenados por título y, con el mismo título, por ISBN. `q` busca en el título o el autor sin distinguir mayúsculas (ni ignorar acentos); sin `q` lista todo. `page` ≥ 1 (1 por defecto), `pageSize` de 1 a 50 (20 por defecto) y `total` cuenta toda la búsqueda | `400` (un parámetro inválido o desconocido) |
| `GET` | `/books/:isbn` | `200 { isbn, title, author, price: { amount, currency } }`; acepta el ISBN con o sin guiones y devuelve el normalizado | `404 NOT_FOUND` (no existe o está inactivo) · `422 INVALID_ISBN` (mal formado o con el dígito de control incorrecto) |

| `PATCH` | `/admin/books/:isbn` (**administrador**) | `200 { isbn, title, author, price: { amount, currency }, active }`. Cuerpo: cualquier subconjunto de `title`, `author`, `price: { amount, currency? }` y `active`, pero al menos uno; `active: false` desactiva el libro (no se borra) y `true` lo reactiva. La moneda no se cambia. Se aplica todo o nada. Un cambio de precio no afecta a pedidos ya hechos | `400` (cuerpo vacío, campo inválido, `null` o de más) · `401` · `403` · `404 NOT_FOUND` (el libro no existe) · `422 INVALID_ISBN`, `INVALID_PRICE`, `INVALID_CURRENCY`, `INVALID_BOOK`, `CURRENCY_CANNOT_CHANGE` |
| `POST` | `/admin/stock/:isbn/additions` (**administrador**) | `201 { isbn, available, reserved }` con el nivel resultante. Cuerpo: `{ "quantity": 25 }`, un entero de 1 a 100 000 que se **suma** a lo disponible (no es un valor final). Lo disponible no puede pasar de 1 000 000. No se guarda un historial de cargas | `400` (quantity falta, no es un entero de 1 a 100 000, o hay campos de más) · `401` · `403` · `422 INVALID_ISBN`, `STOCK_ITEM_NOT_FOUND` (el libro no tiene registro de stock), `STOCK_LIMIT_EXCEEDED` |
| `GET` | `/admin/orders?customerId=&cursor=&limit=` (**administrador**) | `200 { items[…], nextCursor }`: los pedidos del cliente, del más reciente al más antiguo. Cada uno trae lo mismo que `GET /orders/:id` más `createdAt` (ISO, UTC) y `shippingAddress` (`null` en un pedido anterior a la dirección). `limit` de 1 a 50 (20 por defecto). `nextCursor` es un texto opaco que se pasa tal cual en `?cursor=` para pedir la página siguiente, y es `null` en la última. Un cliente sin pedidos recibe `items: []` | `400` (`customerId` falta o no es un UUID, `limit` fuera de rango, cursor inválido o parámetro desconocido) · `401` · `403` |
| `GET` | `/me/orders?cursor=&limit=` (**comprador**) | `200 { items[…], nextCursor }`: los pedidos de quien tiene la sesión, con la misma forma y paginación que el historial de administración (con la dirección de envío). No admite `customerId` | `400` (`limit` fuera de rango, cursor inválido o parámetro desconocido, `customerId` incluido) · `401` · `403` |
| `POST` | `/auth/register` (público) | `201 { id, email, role: "BUYER" }`. Cuerpo `{ email, password }`: el correo se guarda recortado y en minúsculas; la contraseña, de 10 a 128 caracteres sin recortar. **No inicia sesión.** El rol no se elige: un campo `role` es un `400` | `400` (campos que faltan, que no son texto o de más) · `409 EMAIL_ALREADY_REGISTERED` · `422 INVALID_EMAIL`, `WEAK_PASSWORD` (corta, larga, una contraseña común o igual al correo) · `429` |
| `POST` | `/auth/login` (público) | `200 { accessToken, tokenType: "Bearer", expiresIn, refreshToken, user: { id, email, role } }`. `expiresIn` son los segundos del token de acceso (900 por defecto). La respuesta lleva `Cache-Control: no-store` | `400` · `401 INVALID_CREDENTIALS` (siempre igual: correo desconocido, mal escrito o contraseña equivocada) · `429` |
| `POST` | `/auth/refresh` (público) | `200` con la misma forma que el login: un par de tokens nuevo. El token de refresco **sirve una sola vez** | `400` · `401 INVALID_REFRESH_TOKEN` (desconocido, vencido, revocado o **ya usado**: reusar uno usado revoca la sesión entera) · `429` |
| `POST` | `/auth/logout` (público) | `204` sin cuerpo; revoca la sesión del token de refresco. Responde `204` también con un token desconocido o ya cerrado | `400` · `429` |

| `GET` | `/health/ready` | `200` si la BD responde (readiness; lo usa el balanceador) | `503` |
| `GET` | `/health/outbox` | `200` si el relay de esta instancia sigue completando vueltas; informa `failed` y `due` (lo usa el monitoreo) | `503` |
| `GET` | `/docs` | Swagger UI | — |

**Un pedido tiene una sola moneda.** Si el carrito mezcla libros en monedas distintas, `POST /orders` responde `422 CURRENCY_MISMATCH`. El pedido se cobra en esa moneda (`PEN` o `USD`): `charged.currency` la indica, y el costo de envío y el mínimo de envío gratis dependen de ella. Una moneda sin reglas de precio responde `422 UNSUPPORTED_CURRENCY`.

**Forma del cuerpo de `POST /orders` (`400`):** no lleva `customerId` (el cliente es el del token; si viene, es un `400`); `cardToken` es un texto no vacío (hasta 255 caracteres); `items` es una lista de 1 a 100 líneas con `isbn` (texto no vacío, hasta 32 caracteres) y `quantity` (entero ≥ 1). `shippingAddress` es obligatorio: un objeto con `recipient`, `phone`, `line1`, `district`, `province` y `department` (texto no vacío, hasta 100, 20, 200, 60, 60 y 60 caracteres) y `reference` opcional (hasta 200). Los espacios de los extremos se recortan. Cualquier otro campo se rechaza, así que el cliente no puede mandar precios ni totales. Una lista vacía o una cantidad que no es un entero ≥ 1 se rechazan aquí, con `400`, antes de llegar al dominio.

**Reglas del pedido que `POST /orders` responde con `422`:** `INVALID_SHIPPING_ADDRESS` (la dirección tiene un teléfono que no es un teléfono —dígitos, espacios, `+`, `-` y paréntesis, con al menos 6 dígitos— o caracteres de control como saltos de línea), `INVALID_ISBN` (ISBN mal formado o con el dígito de control incorrecto), `MAX_QUANTITY_EXCEEDED` (más de 10 unidades del mismo libro, sumando líneas repetidas) y `PRICE_MISMATCH` (el mismo libro con dos precios distintos). Las reglas `EMPTY_ORDER` e `INVALID_QUANTITY` siguen existiendo en el dominio, pero por HTTP las intercepta antes la validación del cuerpo.

**Idempotencia de `POST /orders`.** `Idempotency-Key` es un UUID que el cliente genera una vez por intento de compra. Repetir la misma clave con el mismo carrito devuelve el mismo `201` sin cobrar de nuevo; mientras la primera petición sigue en curso, `409 CHECKOUT_IN_PROGRESS`; si el intento anterior falló, `422 PREVIOUS_ATTEMPT_FAILED` (hay que usar una clave nueva); con otro carrito, `422 IDEMPOTENCY_KEY_REUSED`. El ISBN con o sin guiones y la dirección con o sin espacios sobrantes cuentan como el mismo carrito; **otra dirección con la misma clave es otro carrito** (`422 IDEMPOTENCY_KEY_REUSED`).

**El token de la tarjeta** (`cardToken`) solo viaja a la pasarela de pago: no se guarda ni aparece en ninguna respuesta de error ni en los logs. Con la pasarela simulada de desarrollo, `tok_declined` da `422 PAYMENT_DECLINED` y `tok_error` un `500`; cualquier otro token se aprueba.

**Autenticación.** La sesión viaja en `Authorization: Bearer <accessToken>`; nunca en la URL, el cuerpo ni una cookie. El token de acceso es un JWT firmado (HS256) que vale `ACCESS_TOKEN_TTL_SECONDS` (900 por defecto) y solo lleva el id del usuario (`sub`) y su rol: no lleva el correo. El token de refresco es un texto opaco de 43 caracteres: se cambia en `POST /auth/refresh` por un par nuevo y el anterior deja de servir; presentar uno ya usado se toma por un robo y revoca toda esa sesión (incluido el token nuevo), y dos renovaciones simultáneas con el mismo token cuentan como reutilización. El cierre de sesión no invalida el token de acceso ya emitido, que vale hasta que venza. Toda ruta exige sesión salvo el catálogo (`GET /books…`), `/health/*`, `/docs*` y `/auth/*`.

**Errores de acceso** (siempre `{ statusCode, errorCode, message }`): `401 UNAUTHENTICATED` (falta el token, está mal formado, alterado o de otro esquema; con `WWW-Authenticate: Bearer`), `401 TOKEN_EXPIRED` (el token es auténtico pero venció: el cliente debe renovar la sesión), `403 FORBIDDEN` (se sabe quién es, pero su rol no sirve para esta ruta) y `429 TOO_MANY_REQUESTS` (con `Retry-After`, en segundos). Los mensajes nunca repiten el token ni lo que se mandó.

**Roles.** `BUYER` (un comprador: compra y ve sus pedidos, con `POST /orders`, `GET /orders/:id` de los suyos y `GET /me/orders`) y `ADMIN` (la administración `/admin/*` y `GET /orders/:id` de cualquiera). Un administrador no es un cliente: no puede comprar. Los administradores no se crean por la API sino con `pnpm run admin:create`.

**Límite de intentos** (en memoria, por ventana de `RATE_LIMIT_WINDOW_SECONDS`, 60 por defecto): `POST /auth/login` por dirección (20) y por correo (5, el mismo correo desde cualquier dirección), `POST /auth/register` por dirección (10) y `POST /auth/refresh` más `POST /auth/logout` juntos por dirección (30). Cuentan todos los intentos, también los correctos y los de un cuerpo inválido. El resto de la API no se limita.

**Un comprador recién registrado** tiene su cliente en Ventas alrededor de un segundo después (lo crea un consumidor del evento `identity.user.registered`). Si compra justo entonces recibe `404 NOT_FOUND`; basta reintentar.

**El registro no verifica el correo.** `409 EMAIL_ALREADY_REGISTERED` revela que un correo ya tiene cuenta (no hay otra forma de avisarlo sin verificación); en cambio el login nunca lo revela.

**CORS y cabeceras.** Sin `CORS_ORIGINS` no se envía ninguna cabecera CORS; con ella, solo los orígenes de la lista (comparados enteros y exactos) reciben `Access-Control-Allow-*`, y la petición previa (`OPTIONS`) se responde sin token. Se permiten `GET`, `POST` y `PATCH`, las cabeceras `Authorization`, `Content-Type`, `Idempotency-Key` y `X-Request-Id`, y se exponen `X-Request-Id` y `Retry-After`; no se admiten credenciales (cookies). Todas las respuestas llevan las cabeceras de seguridad de `helmet` (`X-Content-Type-Options`, `Strict-Transport-Security`, una política de contenido estricta, etc.).

**Administración (`/admin/*`).** Exige un token de un administrador: sin token `401`, con el de un comprador `403`. Ya no depende de ninguna variable de entorno y funciona igual en producción, y `/docs` las muestra con la etiqueta `admin`.

**Los precios entran como salen:** `{ "amount": "45.00", "currency": "PEN" }`, con el monto en texto (un número se rechaza con `400`), punto decimal y hasta 2 decimales.

**Todas las respuestas incluyen el header `X-Request-Id`.** Si la petición lo trae (con formato válido), se devuelve el mismo; si no, uno generado.

**Formato de los montos:** todo monto en la API es un objeto con **texto de 2 decimales y moneda**: `{ "amount": "45.00", "currency": "PEN" }`. Vale para `charged`, `unitPrice` y `price`, así que un libro se ve igual en `GET /books/:isbn` y en la línea del pedido. Punto como separador decimal, sin separador de miles. En `GET /orders/:id`, `unitPrice` (escala 6 en la BD) se muestra con 2 decimales; el valor completo queda en la BD para la facturación.

```ts
// catalog/infrastructure/book/get-book-price.handler.ts (fragmento)
return {
  isbn: book.isbn, title: book.title, author: book.author,
  price: { amount: book.price.toFixed(2), currency: book.currency },   // Prisma.Decimal → texto
};
```
