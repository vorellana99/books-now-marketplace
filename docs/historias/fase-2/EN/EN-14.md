# EN-14 La matriz de cada fase, con una sola tabla de historias y una de habilitadores

> **Estado:** ⬜ aprobada por el usuario (las opciones recomendadas de la propuesta del 2026-10-31: orden por ID, encabezados a secas y sección vacía con una línea), **registrada solo como documentación: ninguna tarea está ejecutada**. Las tareas se ejecutan cuando el usuario lo pida.

| Campo | Contenido |
|---|---|
| Para | Que la matriz de cada fase tenga exactamente dos tablas, una de historias y una de habilitadores, sin separar «Abiertas» de «Cerradas» |
| Porque | Hoy cada tipo se parte en dos tablas con columnas distintas y una historia cambia de tabla al cerrarse, aunque el estado ya dice si está abierta o cerrada |
| Ligado a | La [guía de desarrollo](../../../guia-de-desarrollo.md), que fija cómo se lleva el estado del trabajo |

## Lo que hay hoy (con su fuente)

| Hecho | Fuente |
|---|---|
| Cada matriz de fase tiene, por tipo, una subsección «Abiertas (n)» con todas las columnas y otra «Cerradas (n)» con solo ID, nombre, ligado o épica, estado y «Cierre y tiempo» | `docs/historias/fase-1/matriz.md`, `docs/historias/fase-2/matriz.md` |
| Las columnas están en `COLUMNAS`, indexado por (tipo, abiertas): cuatro listas, dos de ellas con «Cierre y tiempo» | `scripts/historias.py` (`COLUMNAS`) |

| La columna «Fechas y tiempo» ya sirve para una fila cerrada: escribe «inicio → cierre · tiempo» y «en curso» mientras no hay cierre | `scripts/historias.py` (`_celda_matriz`) |
| Las filas ya salen ordenadas por ID dentro de cada grupo | `scripts/historias.py` (`sort_key`, `matrix_cells`) |
| El índice de fases del README de historias cuenta «n abiertas · m cerradas» por tipo con `is_closed`, sin leer las subsecciones | `scripts/historias.py` (`render_index`) |
| Siete menciones de «Abiertas», «Cerradas» o «Cierre y tiempo» en el script y seis en sus pruebas | grep del 2026-10-31 en `scripts/` |
| El README de historias explica «Abiertas y Cerradas» y las fechas por grupo, y la guía de herramientas dice que la matriz lleva «Abiertas» y «Cerradas» | `docs/historias/README.md` (filas «Abiertas y Cerradas» y «Fechas y tiempo»), `docs/herramientas-de-trabajo.md` (fila «Matriz de historias») |
| `docs/avance.md` (congelado) y los habilitadores EN-03 y EN-12 mencionan las dos subsecciones como lo que era verdad entonces | grep del 2026-10-31 |

## Criterios

| Dado | Cuando | Entonces |
|---|---|---|
| La matriz de una fase | Se genera | Tiene un título por tipo, `## Historias` y `## Habilitadores`, y bajo cada uno una sola tabla; no hay subsecciones «Abiertas» ni «Cerradas» |
| Las historias de una fase | Se listan | Una sola tabla con las columnas ID, Historia, Épica, Estado, API, Web, Cambios de producto, Tareas y Fechas y tiempo, para historias abiertas y cerradas por igual |
| Los habilitadores de una fase | Se listan | Una sola tabla con las columnas ID, Habilitador, Ligado a, Estado, Tareas y Fechas y tiempo |
| Una fila de una historia o un habilitador cerrado | Se escribe | Su columna «Fechas y tiempo» dice «inicio → cierre · tiempo», y la de uno abierto, «inicio → en curso · tiempo» |
| Las filas de una tabla | Se ordenan | Por ID, sea cual sea su estado, de modo que una historia no cambia de sitio al avanzar |
| Un tipo sin filas en la fase (la fase 1 no tiene habilitadores) | Se genera la matriz | Conserva su título y una línea «_No hay habilitadores en esta fase._» en vez de la tabla |
| El índice de fases del README de historias | Se genera | Sigue mostrando «n abiertas · m cerradas» por fase y tipo |
| Un documento vivo | Describe la matriz | No habla de «Abiertas» ni «Cerradas» como tablas; los congelados y los habilitadores cerrados conservan su texto |

## Listo cuando

Las matrices de las fases 1 y 2 tienen solo las dos tablas por tipo, ordenadas por ID y con las mismas columnas para filas abiertas y cerradas, el índice de fases conserva sus conteos, ningún documento vivo habla de las subsecciones y pasan el comprobador, las suites de `scripts/` y las pruebas de convenciones de documentos.

## Detalle de las tareas

### EN-14.1 Una sola tabla por tipo en la matriz de cada fase

**Se comprueba**

- [ ] `render_phase` escribe, por tipo, un título `## Historias` o `## Habilitadores` y una sola tabla con todas las filas de ese tipo, sin subsecciones «Abiertas» ni «Cerradas»
- [ ] `COLUMNAS` tiene una sola lista por tipo (historias: ID, Historia, Épica, Estado, API, Web, Cambios de producto, Tareas, Fechas y tiempo; habilitadores: ID, Habilitador, Ligado a, Estado, Tareas, Fechas y tiempo) y desaparece «Cierre y tiempo»
- [ ] las filas salen ordenadas por ID aunque mezclen estados, y la fila de una cerrada dice «inicio → cierre · tiempo»
- [ ] un tipo sin filas conserva su título y la línea «_No hay historias en esta fase._» o «_No hay habilitadores en esta fase._»
- [ ] el índice de fases del README de historias sigue contando «n abiertas · m cerradas»
- [ ] pruebas escritas antes (las que parten la matriz en «Abiertas» y «Cerradas» se reescriben), con mutaciones sobre el orden, las columnas y el texto de vacío; las matrices de las fases 1 y 2 quedan regeneradas

### EN-14.2 Reapuntar los textos que describen la matriz

**Se comprueba**

- [ ] el README de historias describe la matriz con una tabla por tipo y fechas «inicio → cierre · tiempo» para cualquier estado, sin la fila «Abiertas y Cerradas»
- [ ] la leyenda de la matriz y la fila «Matriz de historias» de la guía de herramientas dicen lo mismo
- [ ] lo congelado (`docs/avance.md`) y los habilitadores cerrados conservan su texto
- [ ] una prueba de documentación prohíbe hablar de «Abiertas» y «Cerradas» como tablas en los documentos vivos; sin enlaces rotos

## Riesgos

- Seis pruebas del script asumen las dos subsecciones; hay que reescribirlas antes de cambiar el generador, y no confundir el conteo del índice (que sí sigue) con las tablas.
- Con una sola tabla, la fase 1 mezcla 16 historias cerradas y 4 en curso: el orden por ID las intercala y la columna Estado tiene que bastar para distinguirlas.
